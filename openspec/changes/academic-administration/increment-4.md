# Incremento 4: disponibilidad de tareas y prórrogas

Especificación antes del código. T2a / LMS-016/021/022 / MDL-003..005. El turno anterior produjo código y pruebas RB1–RB5: progreso verificado. Este incremento no sustituye los adjuntos, reentregas ni el resto del objetivo.

## Reglas y aceptación
- DT1: tarea tiene opensAt, dueAt, closesAt opcionales, RFC3339 con zona; almacenamiento timestamptz y respuestas UTC. Campos null eliminan límites. Cuando ambos existen: opensAt <= dueAt <= closesAt y opensAt <= closesAt. Borrador de calendario usa versión de actividad y publicar aplica fechas. Lecturas rechazan calendario. Datos previos quedan sin límites.
- DT2: backend permite guardar/enviar solo desde apertura inclusive y antes de cierre exclusivo. Pasar vencimiento permite entregar, con estado tardío. Leer instrucciones y devolución continúa permitido siempre: el cierre afecta entregas, no acceso educativo. Reloj del navegador nunca autoriza operaciones. Reenvío idéntico de entrega ya enviada sigue idempotente incluso después de cierre. Cada envío guarda effective_due_at y late como evidencia histórica inmutable; cambiar calendario no cambia esa clasificación.
- DT3: docente asignado puede conceder o revocar prórroga individual solo a estudiante vinculado e inscrito en la tarea publicada. Se versiona por par lesson/student, con motivo obligatorio 1..1000 y auditoría. La prórroga solo amplía dueAt/closesAt existentes; no crea un vencimiento cuando no lo había ni acorta plazos. Revocar usa null/null y conserva revisión/auditoría. Ajustar calendario general usa el máximo de fecha base y prórroga; si se elimina un límite general no lo reintroduce una prórroga previa. Si después se introduce un cierre general anterior a una prórroga ya concedida, el cierre efectivo se amplía al menos hasta ese vencimiento para conservar coherencia. Apertura no admite excepción individual en este incremento.
- DT4: todo acceso comprueba objeto/rol. Un estudiante consulta solo su disponibilidad; no puede configurar fechas ni prórrogas. Conflictos de versión 409 y configuración inválida 400; horario cerrado 409 con mensaje específico. Bloqueos de filas: lección antes que matrícula/entrega; lectura del reloj de DB después de adquirir bloqueos. Publicación y cambio de prórroga no se intercalan con un envío protegido.
- DT5: UI docente edita calendario y prórroga con fechas explícitas UTC; no convertir silenciosamente horas locales/DST. Alumno ve apertura, vencimiento, cierre efectivos, prórroga aplicada y estado actual, con zona UTC visible. Formulario deshabilitado si todavía no abre o cerró; servidor vuelve a validar al guardar. Aviso distingue retraso de cierre, error conserva texto, reabrir página actualiza disponibilidad. Entregas docentes muestran a tiempo/tardía; no aplicar penalización automática.

## Datos y contratos
Migración 004: columnas de horario en authored_activities y lessons; assignment_extensions PK(lesson_id,user_id), versión y fechas, FK a lessons/users; extension_revisions audit; submissions effective_due_at nullable y late bool default false. Sin borrar ni reinterpretar datos previos.

PUT /teacher/activities/{activityId}/schedule {version,opensAt,dueAt,closesAt} -> Activity. Publicación aplica calendario junto a contenido/evaluación. Activity incluye tres fechas nullable.
GET /lessons/{lessonId}/availability -> {opensAt,dueAt,closesAt,serverNow,state:upcoming|open|late|closed,extended:boolean}; solo assignment inscrita.
GET /teacher/activities/{activityId}/extensions?page=1 -> {items:[{studentId,alias,version,dueAt,closesAt,reason}],page,pageSize:20}; roster enlazado e inscrito, aun sin excepción (versión 0).
PUT /teacher/activities/{activityId}/extensions/{studentId} {version,dueAt,closesAt,reason} -> misma fila; default version0 crea, posteriores exigen revisión exacta. Filtro course_staff + teacher_students + enrollment; no confiar en identidad de cliente para rutas de estudiante.
Submission añade late y effectiveDueAt. OpenAPI y tipos generados coherentes. 401/403/404/409/400/503 siguen semántica establecida; sesiones/Origin/no-store vigentes.
